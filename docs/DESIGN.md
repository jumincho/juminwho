# DESIGN.md — 몽글몽글 코지 디자인 가이드

이 사이트를 고치는 사람과 AI 에이전트를 위한 규칙입니다. 판단 기준은 이 문서에, 반복해서 쓰는 값은
`src/styles/tokens.css`에 있습니다. 둘이 어긋나면 토큰을 고칩니다.

## 이 사이트는

AI 연구자이자 박사과정생 조주민의 한 페이지 프로필입니다. 채용 담당자, 공동 연구자, 리뷰어가 **누구인지,
무엇을 했는지, 어떻게 연락하는지**를 빠르게 확인하는 곳입니다. 분위기는 말랑하고 포근하게(몽글몽글, cozy)
가져가되, 내용은 이력서처럼 정확하고 읽기 쉬워야 합니다. 귀여움은 장식에서, 신뢰는 타이포그래피와 정보 구조에서
나옵니다.

## 우선순위

1. 사실이 정확하다. 콘텐츠는 `src/data/profile.ts`에만 있습니다.
2. 375px부터 1440px까지, 다섯 언어, 라이트와 다크, 모션을 켜거나 끈 상태 모두에서 편하게 읽힌다.
3. 포근하다. 둥근 모양, 크림과 코코아 색, 파스텔 톤, 천천히 떠다니는 블롭을 씁니다.

## 시각 체계

**색.** 표면은 `--bg`(페이지), `--bg-sunk`(푸터), `--surface`(카드), `--surface-glass`(헤더)를 씁니다. 글자는
`--ink` / `--ink-soft` / `--ink-faint` 세 단계이고, 모든 파스텔 틴트 위에서도 4.5:1(WCAG AA) 이상입니다. 파스텔
톤은 여섯 가족(peach, butter, sage, sky, lilac, rose)이며 가족마다 세 값을 가집니다.

- `--{tone}`: 틴트. 패널이나 칩의 바탕에 씁니다.
- `--{tone}-ink`: 틴트 위의 글자와 아이콘에 씁니다.
- `--{tone}-pop`: 점이나 블롭 같은 장식에만 씁니다. 글자에는 쓰지 않습니다.

요소에 `data-tone="sage"`처럼 톤을 지정하면 그 안에서 `--tone`, `--tone-ink`, `--tone-pop`을 쓸 수 있습니다
(`tones.css`). 배정은 다음과 같습니다.

| 곳 | 톤 |
| --- | --- |
| 논문 / 경력 / 학력 / 수상 패널 | sage / peach / sky / butter |
| Jumin 시계 패널 | lilac |
| 시계의 상태: 취침 / 출근 준비 / 근무 / 양자 중첩 | sky / peach / butter / lilac |
| 역할 / 소속 / 위치 / 나이 행 | lilac / sky / sage / rose |
| LinkedIn / GitHub 버튼 | sky / lilac |
| 언어 메뉴, GitHub 프로필의 언어 알약 | lilac |

`--accent`는 링크 호버와 포커스 링에만, `--alias`는 "JUMIN WHO?"에만 씁니다. `--alias`는 명도 대비가 3.6:1이므로
큰 글자에만 씁니다. 순수한 검정과 흰색, 형광·네온 색, 회색 그림자는 쓰지 않습니다. 예외는 국기뿐입니다. 국기의
나라 색은 바꿀 수 없으므로 토큰이 아니라 `src/components/Flag.tsx`에 그대로 적습니다.

**타이포.** 모두 Fontsource로 직접 호스팅합니다.

- Fredoka: 이름과 제목에 쓰는 둥근 디스플레이 서체.
- Nunito: 본문 서체. 숫자 폭이 같아서 나이 카운터와 시계가 흔들리지 않습니다. Fredoka의 숫자는 폭이 달라서
  바뀌는 숫자에는 쓰지 않습니다.
- Jua: 한글 디스플레이 서체. `vite-plugins/hangulFont.ts`가 빌드할 때 두 서브셋으로 나눕니다. 조주민 세 글자만
  담은 약 2kB짜리는 CSS 안에 직접 넣어 모든 언어에서 쓰고, `profile.ts`에 쓰인 나머지 한글 전체(약 58kB)는 따로
  떼어 페이지가 한국어일 때만 불러옵니다. 굵기가 하나뿐이라 한국어에서는 가짜 굵게(`font-synthesis-weight`)를
  끕니다.
- 중국어, 일본어, 한국어 본문: 방문자 기기의 시스템 글꼴을 씁니다. 글꼴 목록은 토큰 `--cjk-ko`, `--cjk-ja`,
  `--cjk-sc`(간체), `--cjk-hk`(번체)에 있고, `<html lang>`에 따라 `--font-cjk`가 바뀝니다. Fredoka와 Nunito에
  없는 글자만 이 글꼴로 그려지므로 숫자와 라틴 글자는 어느 언어에서나 같습니다.
- 줄바꿈: 한국어는 어절 단위(`word-break: keep-all`), 중국어와 일본어는 글자 단위에 엄격한 금칙
  (`line-break: strict`)을 쓰고, 일본어는 브라우저가 알아볼 수 있으면 문절 단위(`word-break: auto-phrase`)로
  끊습니다.

제목은 문장형 대소문자로 쓰고 영문 대문자 라벨은 이름에만 씁니다. 본문은 16px, 행간 1.65입니다.

**모양.** 반경은 `--radius-sm/md/lg/xl/pill`(10/16/24/36/999px)만 씁니다. 사진, 배지, 패널 모서리 장식은 블롭
윤곽 세 가지(`--blob-1..3`) 가운데 하나를 씁니다. 각진 모서리는 쓰지 않습니다.

**그림자.** 따뜻한 갈색을 여러 겹 쌓은 `--shadow-sm/md/lg`만 씁니다. 다크에서는 검정 기반으로 바뀝니다.

**간격.** 4px 단위 `--space-1` … `--space-9`만 쓰고, 새 값은 만들지 않습니다.

**레이아웃.** 콘텐츠 최대 폭은 72rem입니다. 위에서부터 떠 있는 헤더, 히어로, Jumin 시계 패널, 파스텔 쿠션 패널
네 개(논문 → 경력 → 학력 → 수상·자격), 구름 모양 푸터 순서입니다. 시계 패널은 내비게이션에 넣지 않습니다. 패널
안은 다음처럼 짭니다.

- 타임라인: `기간 칩 | 점과 점선 | 내용`. 44rem 아래에서는 기간이 내용 위로 올라갑니다. 진행 중인 항목의 점은
  은은하게 빛납니다. 예정된 끝 날짜는 기간 칩 아래(좁은 화면에서는 옆)에 점선 테두리 `expected` 태그를 따로
  붙입니다. 그래서 모든 기간 칩의 폭이 같습니다.
- 논문: 종이 카드 격자. 카드 맨 위에 학회 칩과 개최지(원형 국기 스티커 + 도시와 나라)를 나란히 둡니다. 본인
  이름은 굵게 쓰고 형광펜 줄을 긋습니다.
- 수상·자격: 스티커 카드 격자.

**헤더.** 유리처럼 비치는 알약 모양 바입니다. 왼쪽부터 워드마크, 내비게이션, 언어 버튼, 테마 토글 순서이고,
폭에 따라 이렇게 바뀝니다.

| 폭 | 내비게이션 |
| --- | --- |
| 60rem 이상 | 아이콘 + 라벨 |
| 40–60rem | 라벨만 |
| 40rem 미만 | 아이콘만 (라벨은 스크린리더용으로 남김), 둥근 버튼 36px |
| 26rem 미만 | 간격을 없애고 워드마크를 조금 줄임, 둥근 버튼 32px |
| 22rem 미만 | 이름을 숨기고 마스코트만 |

## 아이덴티티 요소 (반드시 유지)

- **"JUMIN WHO?" 전환.** 마우스를 이름에 올리거나 페이지를 48px 넘게 스크롤하면, 히어로의 이름과 헤더의 워드마크가
  젤리처럼 눌렸다가 통통 튀며 "JUMIN WHO?"로 바뀝니다(`NameFlip`). 두 얼굴이 한 칸에 겹쳐 있어서 크기가 변하지
  않습니다. 스크린리더는 언제나 실제 이름을 읽습니다. 터치에서는 스크롤로만 바뀝니다.
- **실시간 나이.** 1998-07-10 00:00 KST부터 센 나이를 소수점 8자리로 보여 줍니다. 100ms마다 DOM에 직접 그리고
  React는 다시 렌더링하지 않습니다. 모션 줄이기에서는 1초마다 갱신합니다. 스크린리더에는 만 나이만 알려 줍니다.
- **마스코트 몽글이.** 통나무에 앞발을 걸친 복슬복슬한 아기 판다입니다. 털은 크림색, 귀와 눈 둘레와 앞발은 짙은
  코코아색(순수한 검정이 아님)이고, 볼에는 파스텔 분홍 볼터치가 있습니다. 모든 윤곽에 라테색 테두리를 둘러서
  어두운 배경에서도 귀와 앞발이 묻히지 않습니다. 원본은 `public/favicon.svg` 한 파일이고, 파비콘, 헤더, 사진 옆,
  시계 스위치, 푸터, 앱 아이콘, OG 이미지에 모두 같은 그림을 씁니다. 16px에서도 판다 얼굴로 읽혀야 하니 작은
  장식을 더하지 않습니다.
- **Jumin 시계.** 아래 "Jumin 시계" 절을 따릅니다. 모든 상태 앞에는 "maybe…"(또는 페이지 언어에서 같은 뜻의
  말)를 붙입니다.

## Jumin 시계

히어로 바로 아래의 "What time is it for Jumin?" 패널(`src/sections/JuminTime.tsx`)입니다. 일과표와 문구는
`profile.ts`의 `juminTime`에, 시간 계산은 `src/lib/clock.ts`에 있습니다.

자리를 적게 차지하도록 큰 시계와 상태 카드 두 가지만 둡니다.

- **Local | Jumin 스위치.** 패널 제목 오른쪽(좁은 화면에서는 제목 아래 전체 폭)의 알약 스위치입니다. 라디오 버튼
  두 개라서 Tab과 화살표 키로 고를 수 있습니다. 기본값은 Jumin이고, 고른 값은 `localStorage`의 `juminwho:clock`에
  저장됩니다. 라벨은 언어를 따릅니다(한국어는 "내 시간 | 주민 시간", 일본어는 "ローカル | ジュミン").
- **큰 시계.** 고른 쪽 시간을 24시간제 `HH:MM`과 작은 초로 매초 보여 주고, 아래에 날짜와 시간대 이름·UTC 차이를
  적습니다. 날짜는 페이지 언어의 로캘로 쓰고, 시계는 어느 언어에서나 24시간제입니다. 장소 줄은 두지 않습니다.
- **상태 카드.** 지금 무엇을 하는지를 Jumin 시간(KST) 기준 일과표로 정해 "maybe…"를 붙여 보여 주고, 짧은 한 줄과
  평일/주말 칩을 붙입니다. 카드 색은 상태의 톤을 따릅니다. 일과표 자체나 다음 상태까지의 시각("until …")은
  화면에 보여 주지 않고, 상태만 매분 새로 계산합니다.

  | 요일 | 시간(KST) | 상태 |
  | --- | --- | --- |
  | 평일 | 09:00–21:00 | maybe… working |
  | 평일 | 21:00–01:00 | maybe… in superposition (관측 전까지 여러 상태가 겹친 시간) |
  | 평일 | 01:00–08:00 | maybe… asleep |
  | 평일 | 08:00–09:00 | maybe… getting ready for work |
  | 주말 | 08:00–01:00 | maybe… in superposition |
  | 주말 | 01:00–08:00 | maybe… asleep |

  구간은 시작한 날에 속하므로 금요일 밤 구간은 토요일 01:00까지, 일요일 밤 구간은 월요일 01:00까지 이어집니다.
  평일/주말 칩은 Jumin 쪽 달력 날짜를 따릅니다. 구간이 겹치면 나중에 시작한 구간이 이기고, 빈 시간은 양자 중첩으로
  봅니다. 다른 언어에서는 "maybe…"를 `juminTime.maybe`의 말로 바꿉니다: 也许……(간체), 也許……(번체),
  たぶん…(일본어), 아마도…(한국어).
- 인쇄할 때는 숨깁니다.

## 모션

허용하는 움직임은 모두 느리고 작습니다.

- 배경 블롭 떠다니기: 40–60초 주기
- 사진과 패널 모서리 블롭의 모양 변형: 14–19초 주기
- 마스코트 둥실, 구름 흐름, 반짝이, 손 흔들기
- 하트 박동: 1초 주기, 나이 옆
- 진행 중 타임라인 점의 빛, 시계의 "live" 점: 2.6초 주기
- 시계: 양자 중첩 배지의 원자 회전 16초, 스위치 손잡이 미끄러짐
- 언어 메뉴: 열릴 때 살짝 커지며 내려오기
- 이름 전환: 560ms 스프링
- 호버 시 살짝 뜨기: 3px 이하

모든 애니메이션은 `prefers-reduced-motion: no-preference` 안에만 둡니다. 모션 줄이기를 켜면 1Hz로 갱신하는 나이
카운터와 시계 말고는 멈춥니다. 스크롤에 따라 나타나는 효과, 패럴랙스, 페이지 전환, 자동 재생 캐러셀은 쓰지 않습니다.

## 테마

기본값은 운영체제 설정입니다. 헤더의 해·달 버튼으로 바꿀 수 있고, 고른 값은 `localStorage`의
`juminwho:theme`에 저장됩니다. `index.html`의 인라인 스크립트가 첫 화면을 그리기 전에 `<html data-theme>`를
정하므로 화면이 깜빡이지 않습니다. 색 토큰은 `:root`(라이트)와 `:root[data-theme='dark']`(다크) 두 곳에만
있습니다.

## 언어

English(기본), 简体中文, 繁體中文, 日本語, 한국어 다섯 가지이고, 목록과 순서는 `profile.ts`의 `languages`에
있습니다.

- **언어 메뉴.** 헤더의 테마 토글 왼쪽에 있는 둥근 버튼이 메뉴를 엽니다. 메뉴는 버튼 아래에 매달린 라일락 톤 카드로,
  줄마다 지역 표시(US, CN, HK, JP, KR), 그 언어로 쓴 이름, 현재 언어의 체크 표시가 있습니다. 이름은 페이지
  언어와 상관없이 각자의 글꼴로 그립니다. 라디오 메뉴 항목이라 화살표, Home, End 키로 움직이고 Enter로 고르며,
  Escape나 바깥 클릭으로 닫힙니다.
- **정하는 순서.** 주소의 `?lang=`, 없으면 `localStorage`의 `juminwho:lang`, 없으면 영어입니다. 메뉴에서 고르면
  저장하고 주소에도 `?lang=`을 반영합니다(영어는 매개변수 없음). 그래서 복사한 링크는 같은 언어로 열립니다.
  `index.html`의 인라인 스크립트가 첫 화면을 그리기 전에 `<html lang>`을 정하므로 글꼴과 줄바꿈이 깜빡이지
  않습니다.
- **문구.** 화면의 모든 문구는 `Localized`(`{ en, 'zh-CN', 'zh-HK', ja, ko }`)로 적고, 하나라도 빠지면 타입 검사가
  막습니다. 번체는 홍콩 표기(電郵, 源代碼 등)를 따릅니다. 문구를 새로 넣을 때는 다섯 언어를 한꺼번에 채웁니다.
- **고유 명사.** 논문 제목, 저자, 학회명, 연구실, LinkedIn, GitHub는 번역하지 않습니다. 그 가운데 영어 문장처럼
  긴 것(논문 제목과 저자, 연구실 이름)에는 `lang="en"`을 붙여 어느 페이지에서나 영어 규칙으로 줄바꿈하게 합니다.
- **어순.** 언어마다 순서가 다른 곳은 `labels`에 함수로 적습니다. 장소는 영어에서 "도시, 나라"이고 나머지에서는
  나라가 먼저입니다("대한민국 전주", "日本・東京", "韩国全州"). 소속은 영어에서 "학과, 대학", 나머지에서 "대학
  학과"입니다.
- **지역 표시.** 언어를 국기로 나타내지 않습니다. 언어는 나라가 아니고, 국기 이모지는 Windows에서 글자로
  보이기 때문입니다.

## GitHub 프로필 README

github.com/jumincho 첫 화면의 README(jumincho/jumincho 저장소)도 이 저장소에서 만듭니다. `npm run github-profile`이
`profile.ts`의 내용과 사이트의 토큰, 톤, 서체, 국기, 몽글이로 카드를 그려 옆 폴더의 체크아웃(`../jumincho`)에
씁니다. 그 저장소의 README와 이미지는 직접 고치지 않습니다.

- 순서: 언어 알약 → 히어로 배너 → 알약 링크(포트폴리오, LinkedIn, 연구실) → 이메일 → At a glance와 논문 → 경력과
  학력·수상 → 구름 푸터. 넓은 화면에서는 414px 카드 두 장을 같은 높이로 나란히 놓고, 좁은 화면에서는 한 장씩
  쌓습니다.
- 사이트의 다섯 언어마다 README가 있습니다. 영어 `README.md`가 프로필 첫 화면에 보이고, 나머지는
  `README.<code>.md`입니다. 맨 위의 언어 알약 줄(라일락 톤, 지금 언어에는 체크)이 다섯 README를 서로 잇습니다.
  이미지는 언어별로 `assets/<code>/`에, 알약은 `assets/lang/`에 둡니다. 사이트로 가는 링크(히어로, 포트폴리오
  버튼, 카드, 푸터)는 모두 그 README의 언어로 사이트를 엽니다(`?lang=`).
- 이미지마다 라이트와 다크 SVG가 있고, `<picture>`가 보는 사람의 GitHub 테마에 맞춰 고릅니다.
- 글자는 HarfBuzz로 윤곽선(path)으로 바꿔 넣습니다. GitHub의 이미지 안에서는 폰트를 믿을 수 없기 때문입니다.
  카드 레이아웃은 `scripts/github-profile/cards.css`에 있고 사이트 토큰을 씁니다.
- 중국어, 일본어, 한국어 본문은 개발 의존성으로 설치한 Noto Sans(KR, JP, SC, HK)로 그립니다. 생성기에서는 사이트처럼
  방문자의 시스템 글꼴을 쓸 수 없기 때문입니다. 글자마다 브라우저처럼 글꼴 목록에서 그 글자를 가진 첫 글꼴을
  고르므로, SVG는 Chromium에서 배치한 카드와 똑같이 나옵니다.
- 움직임은 히어로, At a glance, 푸터에만 두고 사이트처럼 느리고 작게 합니다. 이미지에는 호버가 없으므로 이름은
  9초 주기로 저절로 "JUMIN WHO?"로 바뀌었다 돌아옵니다. 모션 줄이기에서는 모두 멈추고 실제 이름만 보입니다.
- 나이는 소수점 4자리로 그립니다. 프로필 저장소의 워크플로(`age.yml`)가 매일 00:05(KST)에 모든 언어의 At a
  glance SVG 안의 숫자만 다시 그립니다.
- 이메일은 `mailto:` 없이 코드 글꼴의 일반 텍스트로 둡니다.
- 외부 서비스 배지(언어 통계, 방문자 수 등)는 넣지 않습니다.

## 콘텐츠 규칙

- 모든 사실은 LinkedIn 프로필이나 인용 가능한 기록으로 확인할 수 있어야 합니다. 예정된 날짜는 `expected`로
  표시합니다. 빈약한 섹션을 지어낸 문구로 채우지 않고, 차라리 섹션을 뺍니다.
- 저자 목록은 빠짐없이 출판 순서대로 쓰고, 본인 이름 표기는 `selfNames`에 넣어 강조합니다.
- 논문은 1차 출처(출판사 PDF, 프로시딩 페이지)로 링크합니다. 1차 출처가 없으면 검색 결과를 걸지 말고 링크 없이
  학회명만 씁니다.
- 기간은 `{ from, to?, expected? }`로 적습니다. `to`가 없으면 "present"로 표시합니다.
- 장소(히어로의 위치 `profile.location`, 논문 개최지 `place`)는 `{ city, country, countryCode }`로 적고, 화면에는
  `PlaceName`이 원형 국기 뒤에 페이지 언어의 어순으로 보여 줍니다(영어는 "도시, 나라"). 국기는 `Flag.tsx`에
  SVG로 그립니다(지금은 한국, 이탈리아, 일본). 그림이 없는 나라는 지도 핀으로 대신하니, 새 나라가 필요하면 그림을
  추가합니다.
- 기관과 지도교수는 공식 페이지로 링크하고, 외부 링크는 새 탭으로 엽니다.
- 이메일은 복사 버튼이 붙은 일반 텍스트로 둡니다. `mailto:` 링크로 만들지 않습니다.
- 화면 문구(인사말, 라벨, 스크린리더용 문장)도 `profile.ts`의 `labels`에 다섯 언어로 둡니다.
- 번역은 사실을 바꾸지 않습니다. 직함과 학위는 그 언어에서 흔히 쓰는 말로 옮기되, 없는 뜻을 더하지 않습니다.

## 하지 말 것

- 지어낸 소개글, 스킬 막대, 숫자 부풀리기
- 날카로운 모서리, 회색 그림자, 강한 그라디언트 글자, 유리 효과 남발(헤더 한 곳만 씀)
- 목록마다 아이콘 붙이기(섹션 배지, 사실 행, 장소 앞 국기에만 씀)
- 국기 이모지. Windows에서는 국기 대신 "IT" 같은 글자로 보이므로 SVG 국기를 씀
- 언어를 국기로 표시하기(언어 메뉴의 지역 표시는 US, CN 같은 글자로 씀)
- 한 언어에만 문구를 넣거나, 고유 명사(논문 제목, 저자, 학회명, 연구실)를 번역하기
- 스톡 이미지나 생성 이미지(사진은 본인 사진 한 장, 장식은 마스코트와 도형만 씀)
- 블로그, 관리자 기능, CMS, Supabase, Mapbox 재도입(2026-09 개편에서 제거함)

  `snapshots/`에 남깁니다. 바뀌기 전과 나란히 놓고 비교하세요.
  - 콘솔 에러, 실패한 요청
  - 가로 넘침, 헤더 내비게이션 넘침
  - 이미지, 아이콘, 폰트 로드
  - 나이 카운터와 Jumin 시계 갱신
  - 호버·스크롤 시 "JUMIN WHO?" 전환
  - 테마 토글, Local | Jumin 스위치
  - 모든 상태가 "maybe…"로 시작하는지, 정해 둔 시각(로스앤젤레스에서 본 KST 10개 시각)의 상태가 일과표와 맞는지
  - 모션 줄이기에서 멈추는지
  - 영어가 아닌 네 언어마다: `<html lang>`, 가로 넘침, 헤더 내비게이션, 번역된 제목과 상태 문구("아마도…" 등),

    사라지는지

  `npm run snapshots -- --readme`로 README 미리보기도 새로 만든다.
- `profile.ts`, 마스코트, 팔레트를 바꿨다면 `npm run github-profile`로 GitHub 프로필 README를 다시 만들고
  jumincho 저장소의 main에 올린다.
